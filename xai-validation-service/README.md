# XAI Validation Service

A FastAPI microservice that validates specialist AI diagnoses and treatment plans for clinical safety before results are returned to the patient. It combines deterministic rule checks, SHAP-based explainability, a constitutional self-critique loop, and a DeepAgent (LangGraph-based) LLM to produce a structured validation verdict.

Runs on **port 8016**. Called twice per patient case by the orchestrator: once after diagnosis, once after treatment planning.

---

## How It Works

```
Request (diagnosis or treatment)
      │
      ├─▶ Step 1: Medical rules pre-filter (medical_rules.py)
      │       Fast keyword/SpO2/severity checks — immediate REJECT if violated
      │
      ├─▶ Step 2: Rule Engine (rule_engine.py)
      │       46 hardcoded + LLM-generated rules loaded from MongoDB
      │       REJECT → hard stop   |   REVIEW → concern injected into LLM query
      │
      ├─▶ Step 3: Explainability pre-computation (diagnosis only)
      │       SHAP attribution from cancer_agent_models.pkl, or LLM fallback
      │       Results stored in ContextVar for attachment to the final response
      │
      ├─▶ Step 4: DeepAgent LLM call
      │       Single call with pre-computed rule checks and explainability injected
      │       Returns JSON: is_validated, confidence_score, recommendation, key_concerns
      │
      └─▶ Step 5: Constitutional Guard (diagnosis only)
              Critique→revision loop enforcing 5 clinical safety principles (P1–P5)
              Falls back to original response if revision produces invalid JSON
              │
              ▼
        Structured ValidationResponse with SHAP factors + latency metadata
```

### Clinical Safety Rules

Rules are loaded at startup from MongoDB (`xai_validation_rules` collection), with a JSON file fallback (`data/xai_validation_rules.json`) if MongoDB is unavailable.

At startup, `rule_generator.py` also extracts additional rules from ChromaDB clinical guidelines (PubMed abstracts) using an LLM — skipped if `LLM_G*` rules already exist in MongoDB.

### Constitutional Principles (P1–P5)

| Principle | Description |
|---|---|
| P1 — Emergency conservatism | CRITICAL severity must not be APPROVED without `emergencyCareNeeded=YES` |
| P2 — Epistemic humility | Confidence ≥ 0.9 only when clinical evidence is unambiguous |
| P3 — Safety-first triage | Emergency symptoms + LOW severity requires explicit justification, else REVIEW |
| P4 — Completeness | APPROVE must include at least one specific clinical observation |
| P5 — Guideline alignment | Response must not contradict retrieved clinical guidelines |

### SHAP Explainability

When `trained_model/cancer_agent_models.pkl` is present (generated by `cancer-agent/scripts/train_models.py`), SHAP attribution is computed across severity, emergency, and cancer-type models. Without the file, a 3-factor LLM explanation is used as fallback.

## API

### `POST /xai-validator/validate-diagnosis`

**Request**
```json
{
  "patient_id": "P001",
  "symptoms": "Chest pain radiating to left arm, diaphoresis, BP 90/60",
  "specialist_agent": "Cardiology_Specialist",
  "diagnosis": {
    "diagnosisDetails": "Presentation consistent with STEMI...",
    "severity": "CRITICAL",
    "emergencyCareNeeded": "YES",
    "hospitalizationNeeded": "YES"
  }
}
```

**Success response**
```json
{
  "is_success": true,
  "payload": {
    "agent": "XAI_Validator",
    "agent_id": "XAI-VALIDATOR-1003",
    "patient_id": "P001",
    "validation_type": "DIAGNOSIS",
    "result": {
      "is_validated": true,
      "confidence_score": 0.92,
      "validation_summary": "Heart attack diagnosis with correct emergency flags. Plan is safe to proceed.",
      "key_concerns": ["Emergency care correctly flagged for CRITICAL severity"],
      "recommendation": "APPROVE",
      "explanation_factors": [...],
      "validator_latency_ms": 1240.5,
      "model_used": "gpt-5.2",
      "explainability_method": "SHAP",
      "rules_triggered": [],
      "constitutional_revised": false
    }
  }
}
```

### `POST /xai-validator/validate-treatment`

Same structure, with `diagnosis_summary`, `severity`, and `treatment_recommendation` fields instead of `diagnosis`.

## Running Locally

```bash
cd xai-validation-service

python -m venv venv
source venv/Scripts/activate   # Windows
# source venv/bin/activate     # Linux / macOS

pip install -r requirements.txt

bash run.sh
# or directly:
uvicorn main:app --app-dir ./src --host 127.0.0.1 --port 8016 --reload
```

### Prerequisites

- MongoDB running with the `xai_validation_rules` collection (or the JSON seed file at `data/xai_validation_rules.json`)
- ChromaDB running on port 8020 (for LLM-generated rules and P5 guideline grounding)
- `OPENAI_API_KEY` set in environment or `.env`
- Optionally: `trained_model/cancer_agent_models.pkl` for SHAP explainability

### Environment Variables

| Variable | Default | Description |
|---|---|---|
| `OPENAI_DEFAULT_MODEL` | `gpt-5.2` | LLM model for the DeepAgent and constitutional guard |
| `OPENAI_API_KEY` | — | Required |
| `XAI_AGENT_ID` | `XAI-VALIDATOR-1003` | Agent identifier in responses |
| `CHROMA_HOST` | `127.0.0.1` | ChromaDB host |
| `CHROMA_PORT` | `8020` | ChromaDB port |
| `MONGODB_URI` | `mongodb://localhost:27017` | MongoDB connection string |
| `MONGODB_DB_NAME` | `agentic_ai_healthcare_db` | Database name |
